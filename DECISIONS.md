## Active Decisions
- **Wger Integration**: Uses client-side `WgerExerciseProvider` with local `exerciseCacheStorage` caching; edge function ingestion into Supabase is planned for future backend migration.
- **Routing**: Using Expo Router for all navigation.
- **Web Splash Animation**: Animations require `Platform.OS !== 'web'` for native driver compatibility on the web splash screen.
- **Avatar Storage Privacy Model**: The `avatars` Supabase Storage bucket is intentionally configured with `public = true` to allow performant direct CDN rendering in React Native `<Image />` and Expo Image without signed-URL latency, token expiry, or complex cache invalidation. Security is enforced through multi-layer controls: (1) anonymous object/bucket listing via PostgREST SELECT is blocked by storage RLS, (2) object mutation and deletion are strictly isolated to authenticated owners via `(storage.foldername(name))[1] = auth.uid()::text`, and (3) `public.profiles` database records containing avatar URLs are protected by user-only SELECT RLS policies. Blind URL guessing is mitigated by cryptographically random 128-bit UUID folder paths combined with millisecond upload timestamps. Private storage with signed URLs was evaluated and rejected because it would break existing production photos and introduce unnecessary latency/offline complexity.
- **Exercise Demonstration Media Architecture (Phase 2, M1)**: Demonstration media resolution is keyed strictly by canonical, stable exercise IDs (never exercise names or fuzzy similarity). The initial foundation uses a local, typed, immutable catalog (`CURATED_EXERCISE_MEDIA_CATALOG`) and a deterministic resolver (`exerciseMediaService`) requiring explicit copyright/license verification and author/source attribution before any asset is cleared for display. Zero database migrations or Supabase tables are created for this feature; production catalog contains only verified assets (empty by default). Existing user-owned custom exercise photos remain strictly isolated from system demonstration media. UI integration (thumbnails, detail viewer, active workout sheet) and broad media asset sourcing are decoupled into subsequent milestones.
- **Exercise Library Search Concurrency & Pagination Deduplication**: Search queries in BeBig 2.0 return ranked candidates in a single unpaginated batch. To eliminate duplicate React child keys (e.g. `.$wger_75`) caused by stale browse pagination triggering during search transitions: (1) filter and search query changes immediately reset `hasMore: false` and `nextOffset: undefined`; (2) `handleLoadMore` immediately exits if `searchQuery.trim().length > 0`; (3) browse and search requests are sequenced using a monotonically increasing request ID ref (`searchReqIdRef`) to ensure out-of-order asynchronous responses cannot overwrite newer search results; (4) list pagination appends deduplicate against existing exercise IDs via a `Set` before merging.
- **Exercise Library Visual Representation & Search Performance (Phase 2, M2 Optimization)**: Letter-based placeholder tiles (e.g. 'BK', 'BP', 'CH') are replaced with a clean, neutral monochrome workout icon fallback to eliminate artificial game-style visual clutter. For responsiveness and smooth 60fps scrolling: (1) search input, category, and source changes query the in-memory cache synchronously in the event handler (0ms local response) while keeping remote API refresh debounced and non-blocking in the background; (2) `damerauLevenshtein` distance calculation uses a single flat typed buffer (`Int32Array`) and word-token matching, eliminating 95%+ of dynamic allocations on the JS thread during fuzzy search; (3) fallback token network requests run concurrently via `Promise.allSettled` with a 2000ms ceiling instead of sequential loops; (4) exercise list items are memoized via `React.memo` with `removeClippedSubviews` enabled on native platforms.
- **Verifiable Skill Workflow Integration**: To ensure Claude-grade engineering discipline, root-cause debugging, and safe Git conventions in BeBig 2.0 without relying on fragile background plugins or context-bloating bulk installations: (1) core engineering skills (`gravitas`, `systematic-debugging`, `test-driven-development`, `code-review-excellence`, `git-commit-message`) reside in `C:\Users\adity\.agents\skills\`; (2) agents select only the task-relevant skill on-demand; (3) when a skill is not mounted in Antigravity's active `<skills>` registry, the agent reads its `SKILL.md` before mutating code; (4) completion reports explicitly distinguish automatic discovery, explicit reading, and specific practices verified; (5) tests are run with the main agent unless a subagent is genuinely necessary and justified.
- **Exercise Demonstration Media Batch 1 & Licensing Attribution (Phase 2, M1 Integration)**: Demonstration media licensing supports `CC-BY-SA-3.0` and `CC-BY-SA-4.0` with mandatory author attribution and source verification in `exerciseMediaService`. Curated the first production batch of 10 verified demonstration assets mapped strictly to canonical exercise IDs (`wger_73`, `wger_75`, `wger_538`, `wger_257`, `wger_91`, `wger_272`, `wger_566`, `wger_348`, `wger_197`, `wger_84`, and canonical seed bindings for `seed-bench-press` and `seed-lateral-raise`). All assets are verified under Creative Commons Attribution-ShareAlike with confirmed 200 OK image and thumbnail URLs, deterministic exact-ID matching, and zero fuzzy or name-based resolution.
- **Expo SDK 57 & Native Development Client Strategy**: Expo SDK ~57.0.25, React Native 0.86.3, and all configured native plugins are preserved without downgrading. Public App Store Expo Go incompatibility with SDK 57 is bypassed using an EAS Development Client build (`npx expo run:ios` / EAS internal dev client) for native iOS verification and iPhone Safari Mobile Web (`http://<LAN_IP>:8081`) for zero-install physical device testing. This prevents brittle SDK regressions and preserves iOS Live Activities and Apple Authentication capabilities.
- **Wger Primary Media Source & Foundational Browse Seed Integration (Phase 2, M1 Fixes)**: Wger is confirmed as the primary legal exercise demonstration media source for BeBig 2.0 (targeting all 279 Wger movements with verified media), rejecting OpenGym due to proprietary GymVisual copyright restrictions. In `exerciseRepository`, foundational seed compound lifts (`SEED_EXERCISES`) are merged into the head of the first unfiltered browse page (`!hasQuery && (!category || category === 'all')`) and deduplicated by canonical exercise ID without duplicating on subsequent pages (`offset > 0`). In `app/exercises/[id].tsx`, detail views integrate `resolveExerciseDemonstration()` with strict priority: (1) user custom photo for custom exercises, (2) approved curated Wger demonstration with author/license attribution, (3) provider images, and (4) clean fallback without broken image placeholders.
- **Canonical Custom Exercise Creation UI Unification**: Custom exercise creation across all application entry points (Exercise Library `app/exercises/new.tsx` and ongoing workout/template picker `src/features/templates/components/ExercisePickerModal.tsx`) is unified under a single canonical component (`CustomExerciseForm`). The modal picker previously used an incomplete form without photo support, muscle inputs, or form cues. `CustomExerciseForm` provides full field parity (Name, Photo picker/preview/replace/remove with private cloud sync, Category chips, Equipment chips, Primary/Secondary muscles, Instructions), consistent validation (`Please enter an exercise name.` and duplicate exercise naming rejection), and dirty-state confirmation. It accepts an `isModal` prop for seamless embedding inside `ExercisePickerModal` without navigation disruptions, preserving ongoing workout state and immediately auto-selecting and appending the created exercise to the active workout session.
- **Search Keyboard Stability & Native Layout Preservation**: React Native virtual keyboard dismissal during rapid typing was root-caused to conditional unmounting of the `<FlatList>` container when results were loading or empty (`exercises.length === 0`). Replaced conditional container unmounting with permanently mounted `ScreenFlatList` / `FlatList` using `ListEmptyComponent` for loading, empty, and error states across both `app/exercises/index.tsx` and `ExercisePickerModal.tsx`. Configured `returnKeyType="search"` and `blurOnSubmit={false}` to guarantee that virtual keyboard focus remains intact throughout search typing and query transitions.
- **Custom Exercise Photo Direct Local URI Priority**: Fixed blank custom exercise image containers by updating `hasCustomPhoto` and `getCustomPhotoUri` in `exerciseMediaService.ts` to inspect `exercise.images[0].url` (where local `file://` or `data:` URIs reside) rather than strictly checking `exercise.photoPath` (which holds a relative Supabase bucket key or `null` in guest mode). In `ExerciseThumbnail.tsx`, user-owned custom photos are prioritized first before evaluating curated demonstration media.
- **Unified Exercise Selection UI (`ExerciseCard`)**: Created the canonical `ExerciseCard` component (`src/features/exercises/components/ExerciseCard.tsx`) shared across the Exercise Library (`app/exercises/index.tsx`) and the Ongoing Workout / Template Picker (`src/features/templates/components/ExercisePickerModal.tsx`). Both entry points display identical 42px thumbnails, exercise names, CUSTOM badges, category and equipment subtiles, and target muscle highlights. Multi-selection checkboxes in the workout picker are integrated alongside the card without layout drift.
- **Cache-First 0ms Exercise Loading & In-Flight Request Deduplication**: Implemented cache-first rendering where `ExerciseListScreen` and `ExercisePickerModal` initialize state synchronously from `exerciseRepository.getCachedExercises()` for instantaneous 0ms display on screen mount. Added in-flight request deduplication (`inFlightListRequests` and `inFlightDetailRequests`) to `WgerExerciseProvider`, mapping concurrent network calls to identical URLs to the same active Promise. Guarded `useFocusEffect` with `isInitialMountRef` in `app/exercises/index.tsx` to eliminate redundant duplicate network fetches on initial mount.
- **Indian Commercial Gym Catalogue Filter & Deduplication**: Designed and implemented intelligent non-destructive catalogue filtering (`src/features/exercises/data/gymEquipmentFilter.ts`) tailored for typical Indian commercial gyms (e.g. Cult.fit, Gold's Gym, Anytime Fitness, local neighborhood gyms). Default browsing highlights movements matching standard equipment (Barbell, Dumbbell, Standard Benches, Cable Machines, Standard selectorized/plate-loaded machines, Pull-up/Dip stations, Bodyweight). Specialized equipment (Gymnastic rings, suspended ribbons, balance boards, sledgehammers, tractor tires, atlas stones) and true contributor duplicates (same movement, category, and equipment) are suppressed from default browsing but remain 100% accessible via direct search and 'All Equipment' filtering. Valid variations (Flat vs Incline vs Decline, Barbell vs Dumbbell, Conventional vs Romanian Deadlift, Close-grip Bench Press) remain distinct.
- **Home Screen Redundant Card Pruning**: Removed the redundant `Exercise Library` card (`testID="browse-exercises-button"`) from `app/home.tsx` to eliminate cognitive redundancy and reclaim vertical space for primary workout actions (Quick Start, Templates/Routines), while preserving the permanent first-class `Exercises` tab in the bottom navigation bar.
- **AI Coach Milestone Deferral**: [SUPERSEDED by 2026-10-30 Removal] Legacy AI Coach feature removed completely to allow a clean slate for future AI development.
- **Exercise Scrolling & Navigation Performance Optimization**: Root-caused scrolling and navigation latency across Exercise Library, Workout Picker, and Exercise Detail: (1) Eliminated unconstrained polling in `ExerciseCard` by gating `CustomExerciseSyncStatus` strictly behind `exercise.isCustom`, removing 30-50 active background intervals from virtualized lists; (2) Implemented `getItemLayout` (107px uniform row height) and tuned virtualization windowing (`windowSize: 7`, `maxToRenderPerBatch: 10`, `updateCellsBatchingPeriod: 50`) on `ScreenFlatList` and `ExercisePickerModal`, eliminating native layout measurement bottlenecks during scrolling; (3) Added `getCachedExerciseByIdSync` in `exerciseCacheStorage` and `exerciseRepository` enabling synchronous 0ms first-frame rendering on Exercise Detail navigation without blank loading spinners; (4) Memoized `ExerciseCard` with custom `areExerciseCardPropsEqual` comparator and passed stable callback in `ExercisePickerModal` to isolate re-renders to only toggled cards; (5) Optimized `useFocusEffect` in `ExerciseListScreen` with custom exercise dirty-version tracking (`customExercisesVersion`) so returning from Exercise Detail preserves existing scroll position and paginated items without triggering redundant network re-fetches; (6) Memoized local candidate search and filter results by revision key in `exerciseCacheStorage` and `exerciseRepository` reducing cached retrieval to 0.04ms.
- **Complete Legacy AI Coach Feature Removal**: Completely decoupled and removed the legacy AI Coach feature from the client codebase (`src/features/coach/`, `app/workout/progress/weekly.tsx`, `app/workout/history.tsx`, `app/home.tsx`, and dedicated coach test suites) so the application behaves as though the feature was never present. Weekly Performance was preserved as a pure mathematical and factual progressive overload review screen with zero layout gaps or loading stalls. Administrative gym staff roles (`AdminRole = 'coach'`, `app/admin/coaches.tsx`, and `coach_client_relationships` table) are strictly preserved as human gym management modules. Backend Edge Functions (`coach-agent`) and database tables are inventoried and retained untouched in production awaiting explicit separate user approval.
- **Active Workout Concurrency, Queue Serialization & Data Loss Prevention**: Implemented comprehensive multi-tier concurrency control and data-loss immunity for active workout sessions: (1) Enforced strict FIFO queue serialization (`activeWorkoutQueue` and `enqueueActiveWorkoutOp` in `workoutStorage.ts`) across all active workout operations (`getActiveWorkout`, `saveActiveWorkout`, `clearActiveWorkout`, `archiveActiveWorkout`, `getAbandonedWorkout`), ensuring `getActiveWorkout` always awaits pending writes before reading storage; (2) Added active draft conflict rejection across `workoutRepository.startWorkoutFromTemplate`, `startEmptyWorkout`, and `startWorkoutFromCompleted`, preventing silent overwrites and requiring explicit resolution (`forceDiscardExisting: true`); (3) Added authoritative active workout conflict prompts with robust `try/catch` error-handled handlers across all user entry points (`app/home.tsx`, `app/workout/start.tsx`, `app/templates/index.tsx`, `app/workout/history/[id].tsx`); (4) Implemented monotonic revision tracking (`version: number` and `updatedAt: string` in `WorkoutSession`) with optimistic concurrency guards rejecting stale snapshots; (5) Added abandoned draft archival (`BASE_ABANDONED_WORKOUT_KEY = 'bebig.workout.active.abandoned'`), 5-item FIFO capacity, `getAbandonedWorkout()` with `parsed.find(isValidSession)` resilience, and `restoreAbandonedWorkout()` to preserve and restore superseded or discarded active sessions with zero data destruction; (6) Enforced user-scoped storage key isolation (`bebig.workout.active_u_<id>`) preventing data leakage across guest and authenticated sessions; (7) Guest migration safeguards: when migrating to an authenticated user who already has an ongoing workout, the guest active session is preserved directly into the user's abandoned archive rather than dropped; (8) Comprehensive 31-test adversarial test suite (`tests/ActiveWorkoutDataLossBug.test.tsx`) covering Categories A–F: creation protection, save/resume integrity, queue concurrency, archive limits & identity, cross-user isolation, and hardware failure recovery.
